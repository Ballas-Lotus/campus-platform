# 校园综合服务平台

学生登录后进入统一工作台，在同一平台内使用四个功能：**讲座预约 / 图书馆座位预约 / 体育场馆预约 / 选课**。

- 四个功能共用一套「资源 + 时间片 + 预约」模型
- 两种库存语义：区间独占（图书馆座位、讲座席位）/ 容量计数（场馆、选课名额）
- 跨资源时间冲突检测（96 格位图）
- 两段式路线：**阶段 0~11 单体交付 ✅ → 阶段 12~15 架构演进 全部完成 ✅**（服务拆分 / MQ / 分库分表+限流 / [演进对比报告](docs/07-架构演进对比报告.md)）
- 数据层现状：**ShardingSphere-JDBC 分库分表（2 库 × 4 片 = 8 分片）** + 基因法单号 + 列加密 + 读扩散索引表（[docs/01 §4](docs/01-数据库设计.md)）
- 高并发现状（阶段 16~21）：**读缓存化**（防击穿/防穿透）+ **教学班读模型**（静态信息/动态余量分离，写后 HINCRBY 增量 + 30 秒对账）+
  **Redis 预扣闸门**（1000 并发只放行 10 个到数据库）+ **幂等与预扣合并 Lua**（写路径 4 次往返 → 2 次）+ 分布式锁 / 接口幂等 / 线程池 / 消费者批量消费 +
  **名额实时同步**（信号推送 + SSE + 查询三层缓存）+ **受理制**（Redis 即真相：受理即裁决、MQ 异步落库、补偿+修正信号+超时裁决兜底，
  一键回退同步链路）（[docs/09](docs/09-高并发改造设计与验收.md) · [docs/13](docs/13-读模型与快路径升级（阶段 19）.md) · [docs/16](docs/16-名额实时同步（阶段 20）.md) · [docs/18](docs/18-受理制异步落库（阶段 21）.md)）

> 规划文档见 `docs/`：`00-从12306移植清单.md`、`00-架构补充说明.md`

## 技术栈

| 层 | 选型 |
|---|---|
| 后端 | Java 17 + Spring Boot 3.2.x + MyBatis-Plus 3.5.x |
| 微服务（阶段 12 起） | Spring Cloud 2023.0.3 + Spring Cloud Alibaba 2023.0.1.0（Gateway / Nacos Discovery / LoadBalancer / **Sentinel 限流**） |
| 数据层（阶段 14 起） | **ShardingSphere-JDBC 5.3.2**（2 库 × 4 片分片 + AES 列加密；含两枚 Boot 3.2 兼容补丁类） |
| 高并发组件（阶段 16~19） | **自研**缓存门面（safeGet 防击穿 + 布隆防穿透）、**教学班读模型**（静态/动态分离 + 写后增量 + 对账自愈）、**Redis 预扣闸门**（Lua 原子 + 回补 + 对账）、**合并 Lua 快路径**（幂等+预扣一次原子）、分布式锁（`SET NX PX` + Lua）、`@CampusIdempotent` 幂等切面、线程池注册表、消费者批量消费（**零新增第三方依赖**，见 [docs/09 §3.1](docs/09-高并发改造设计与验收.md) / [docs/13](docs/13-读模型与快路径升级（阶段 19）.md)） |
| 数据库 | MySQL 8.0（utf8mb4 / utf8mb4_0900_ai_ci）+ Redis 7 |
| 前端 | Vue 3 + Vite + Element Plus + Pinia + Vue Router + Axios |
| 构建 | Maven（后端多模块）/ pnpm（前端） |
| 数据生成 | Python 3 + pandas + numpy + Faker |

## 启动步骤（阶段 12 起：微服务形态）

```bash
# ① 启动中间件（MySQL 8 -> 3308 / Redis 7 -> 6380；RocketMQ 复用 DOVideo 容器 -> 9876）
#    注意：MySQL 需 max_connections=500（compose 已固化——分片后双层连接池需要）
cd campus-platform
docker compose up -d
docker compose ps                     # 等待两个容器 healthy
docker start dovideo-ai-rmqnamesrv-1 dovideo-ai-rmqbroker-1   # 阶段 13 起：RocketMQ（本机 9876）

# ①.5 分库分表迁移（阶段 14 起；一次性，可重放——每次从单体库 campus_platform 重建 8 分片）
docker exec -i campus-mysql mysql -uroot -pcampus123456 --default-character-set=utf8mb4   < resources/database/migrate-sharding.sql
# 输出末段为计数校验：每张表「源计数 = 各分片之和」（广播表为 2 倍=两库副本）

# ② 启动 Nacos（本机常驻，standalone；与 12306 项目共用 8848）
cd /d/dev-tools/nacos/bin
JAVA_HOME="/c/Program Files/Java/jdk-21" "/c/Program Files/Java/jdk-21/bin/java" \
  -Xms512m -Xmx512m -Xmn256m -Dnacos.standalone=true -Dnacos.home="D:/dev-tools/nacos" \
  -jar "D:/dev-tools/nacos/target/nacos-server.jar" \
  --spring.config.additional-location="D:/dev-tools/nacos/conf/" \
  --logging.config="D:/dev-tools/nacos/conf/nacos-logback.xml" nacos.nacos

# ③ 构建并依次启动三个服务（JDK 17）
cd campus-platform/backend
JAVA_HOME=/d/dev-tools/jdk-17 mvn clean package -DskipTests
java -jar campus-user/target/campus-user-0.0.1-SNAPSHOT.jar &          # :9081 用户服务
java -jar campus-service/target/campus-service-0.0.1-SNAPSHOT.jar &    # :9082 核心业务服务
java -jar campus-gateway/target/campus-gateway-0.0.1-SNAPSHOT.jar &    # :9080 网关

# ④ 启动前端（5173，代理 /api -> 网关 127.0.0.1:9080）
cd ../frontend
pnpm install
pnpm dev
```

浏览器打开 <http://localhost:5173>。Nacos 控制台 <http://127.0.0.1:8848/nacos>（nacos/nacos）
可看到 3 个服务在册；**想看扩容/故障接管**：再起一个实例
`java -jar campus-service/...jar --server.port=9083`，杀掉任一实例服务照常。

## 常见问题

- **`pnpm install` 报 `ERR_PNPM_IGNORED_BUILDS`（esbuild / vue-demi）**：pnpm 10+ 默认禁止依赖执行 postinstall 构建脚本。执行 `pnpm approve-builds --all` 批准后重新 `pnpm install`（批准结果记录在 `pnpm-workspace.yaml` 的 `allowBuilds` 字段）。
- **服务启动后首次连库报 `NoSuchMethodError: Representer.<init>()` / `UnsupportedDataTypeConversionException`**：
  ShardingSphere 5.3.2 与 Boot 3.2（snakeyaml 2.x / java.time 合并结果集）的两处已知不兼容——
  已由两个服务模块内置的**类覆盖补丁**（`org.apache.shardingsphere...ShardingSphereYamlRepresenter` / `ResultSetUtil`，源码含补丁说明）修复；
  升级 ShardingSphere ≥ 5.5.3 后可删除。详见 [docs/07 §3](docs/07-架构演进对比报告.md)。
- **压测出现连接超时（`HikariPool-N time out`）**：分片后连接池需按"**单分片峰值并发**"规划——
  外层 128 + 内层 2×128（shardingsphere-config.yaml）+ MySQL `max-connections=500`（compose 已固化），
  三者缺一都会在 100 并发级压测下打爆。
- **curl `127.0.0.1:5173` 不通**：Vite 默认绑定 localhost（Node 优先解析为 IPv6），请使用 `http://localhost:5173` 访问（浏览器不受影响）。
- **复跑压测时数字对不上（如"拦截数 ≠ 请求数 − 名额数"）**：这是上一轮幂等键（5 秒窗口）残留造成的假象——
  压测场景已在每轮开始前自动清理 `campus:idem:*`，手工用 curl 复跑时若跨越 5 秒窗口则不受影响。
- **预扣闸门页显示"暂无活跃计数器"**：计数器按需懒加载（首次请求才创建，TTL 600 秒），
  点一次「一键演示」或正常选课/预约一次即可看到现场。
- **手工清了数据库（如重置压测夹具）却仍提示"名额已满"**：预扣计数器还在（TTL 600 秒）。
  调一次 `POST /api/prededuct/reconcile`（或 `POST /api/prededuct/drop?classId=`）即可；
  正常运维路径下无需人工干预——**服务重启会自动认领并纠偏**（docs/09 §5 第 5 条）。
- **接口莫名返回 50000 且日志里出现 `Unresolved compilation problem`**：IDE 语言服务器把带错的 class
  写进了 `target/classes`。用 `mvn clean package -DskipTests` 重新构建即可（详见 [docs/09 §5](docs/09-高并发改造设计与验收.md)）。
- **想测并发能力**：先读 [docs/10-并发能力测试指南](docs/10-并发能力测试指南.md)——
  正确性用「⚡ 并发压测」8 场景，容量用 `python tools/loadtest.py read`。

  ⑥ **Sentinel 限流**为选课入口削峰（120 并发实测：99 拦截 / 10 抢到 / 0 系统异常，40055 快速失败）；
  ⑦ 容量规划注意"**单分片峰值并发**"（热点分片连接放大，双池 128/128 + MySQL 500）。
- **阶段 16~18 增补（新三层武器，见 [docs/09](docs/09-高并发改造设计与验收.md)）**：
  ⑧ **读缓存化**：热点查询走 Redis（防击穿/防穿透/提交后失效），概览查询 25.63ms → 1.0ms；
  ⑨ **Redis 预扣闸门**：请求先过 Lua 原子"校验+扣减"，不足立即返回（**不占数据库连接**），
     DB 拒绝则回补，30 秒对账自愈——1000 并发抢 10 个课额：拦截 990 / 放行 10 / 0 系统异常，407ms；
  ⑩ **锁 · 幂等 · 线程池**：定时任务分布式锁防多实例重跑、`@CampusIdempotent` 挡重复提交（40060）、
     线程池具名有界且拒绝计数（把"任务被静默丢弃"变成可观测事件）。
- **阶段 19 增补（读模型 + 快路径，见 [docs/13](docs/13-读模型与快路径升级（阶段 19）.md)）**：
  ⑪ **教学班读模型**：静态信息（TTL 600s）与动态余量 Hash（TTL 120s）分离——写后 HINCRBY 增量维护
     （不整键失效、写路径零 SCAN），读一次 pipeline 合并；Hash 过期/漂移由"读回源重建 + 30 秒对账"自愈——
     对照：写后失效 21.4ms / 40 次回源 → 写后增量 3.05ms / 0 次回源；
  ⑫ **合并 Lua**：选课快路径把"幂等判定 + 预扣"焊成一次原子（4 → 2 次 Redis 往返，实测 1.85×），
     冷启动走慢路径、Redis 故障走降级直通——三层语义一致；
  ⑬ **窗口预热与批量消费**：抢课开窗前预热热门课程；站内信消费者"一次拉取、一次 ACK"批处理（50 条 → 4 批）。

- **阶段 20 增补（名额实时同步，见 [docs/16](docs/16-名额实时同步（阶段 20）.md)）**：
  ⑭ **落库后推送信号**：写路径语义零改动——仅在既有 afterCommit 钩子追加"版本+1 与余量同脚本原子写入 + Pub/Sub 广播"
     （`{"id","v","remain"}` 严格三字段，remain 仅供乐观渲染）；实测落库→客户端收到帧 **1ms**、12 条连发合并为 1 帧；
  ⑮ **查询三层缓存**：L1 进程内（键含版本、TTL 2s、信号失效）→ L2 一次 HGETALL 原子快照 → L3 分布式锁+双检按 DB 真值重建
     （超时兜底直返不堆积）——实测 L1 命中率 99.9%（39,857/32），/stock 4.2k QPS 且查询路径不触 MySQL；
  ⑯ **前端实时管线**：乐观渲染（按版本去重防回退）+ 防抖 150ms 合并 + 最大等待 500ms（防饿死）+ 断线自动降级轮询
     （复用同一管线）+ 多标签 BroadcastChannel 共享连接；选课页抽屉新增「⚡ 实时同步 / 轮询校准中」状态标签。

- **阶段 21 增补（受理制，见 [docs/18](docs/18-受理制异步落库（阶段 21）.md)）**：
  ⑰ **受理即裁决**：把裁决点从 MySQL 事务前移到 Redis 原子脚本（幂等/已选/边界/扣减/版本/台账一笔完成），
     HTTP 线程只做"发 MQ → 推信号 → 返回已受理"——**热态 P50 14ms / P95 21ms**（对比：原同步链路含事务提交 ~130ms 级）；
     落库从"用户等待的路径"变成"后台收敛的路径"（150 齐射落库收敛 305ms）；
  ⑱ **正确性四补丁 + 兜底链**：受理台账（对账口径 `capacity−selected−Σpending`）/ 落库行 `op_id`（重放判定"已生效"绝不补偿）/
     补偿以台账为原子闸门 / 消费端"台账不在即跳过"（防超时补偿后迟到消息再落库）——缺一即超卖，逐条给了反例；
     兜底：业务拒绝→补偿+修正信号+站内信+`settled` 回执；消息丢失/进程死亡→5 分钟超时裁决（按 op_id 查库裁决）；
  ⑲ **一键回退与降级层**：`campus.stock.async-select-enabled=false` 整体切回同步链路；受理链路 Redis 异常 → 老链路；
     老链路 Redis 异常 → 幂等放行直通数据库——三层之后正确性始终由唯一索引+条件更新兜底。
