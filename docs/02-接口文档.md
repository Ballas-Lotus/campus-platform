# 02 · 接口文档

> 规则（提示词第 7 节）：统一前缀 `/api`；返回 `{ "code": 0, "message": "success", "data": {} }`；
> 认证用 JWT，放在 `Authorization: Bearer <token>`；错误码集中在枚举类（`common/errorcode` + 各模块 `errorcode`）。

> **阶段 12 起入口为网关 `http://127.0.0.1:9080`**（前端经 Vite 代理指向此处）：

> `/api/internal/**` 为服务间内部接口，**不对外路由**。运行中打开 Nacos 控制台
> （<http://127.0.0.1:8848/nacos>，nacos/nacos）可见服务注册。

## 认证模块（阶段 3）

### 1. 登录

`POST /api/auth/login`　（白名单，无需 token）

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| account | string | 是 | 学号 / 手机号 / 邮箱（**自动识别**：含 `@` → 邮箱；11 位数字且以 1 开头 → 手机号；其余 → 学号） |
| password | string | 是 | 密码（6~32 位；演示账号均为 `123456`） |

**响应示例**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "accessToken": "Bearer eyJhbGciOiJIUzUxMiJ9...",
    "userId": 1,
    "studentNo": "2021001",
    "realName": "林晚秋",
    "role": "STUDENT"
  }
}
```

**错误码**：`40001` 参数校验失败；`40010` 账号或密码错误；`40011` 账号已被禁用。

**常驻测试账号**（2026-10-08）：学号 `test`（密码 123456）——**每次登录自动重置其预约与选课数据**
（释放占用中的时间片与位图 → 清空预约记录/位图/惩罚/周次数；退掉全部已选课程并释放名额；
密码也一并还原为 123456，防止演示改密后被锁在账号外），用于反复体验完整流程而不受历史数据干扰。

**登录态设计**（照搬 12306「JWT + Redis 副本」，见 docs/00 移植清单第 5 节）：

```
JWT 本体（HS512，24 小时）        ← 载体：签名/载荷校验，无状态
  └─ Redis 副本 campus:login:token:{token}（TTL 30 分钟，滑动续期）  ← 开关：可主动失效
       ├─ 每次请求校验副本存在（不存在 → 40101，即使 JWT 未过期）
       └─ 剩余 TTL < 15 分钟时自动续满 30 分钟（12306 原版无续期，此为改进点）
```

### 3. 登出

`POST /api/auth/logout`　（需 token）

删除 Redis 登录态副本 → **旧 token 立即失效**（JWT 本身无法吊销，副本是开关）。

**响应示例**：`{ "code": 0, "message": "success", "data": null }`

### 9.1 讲座报名（阶段 7 · 2026-10-08 报名制）

`POST /api/lecture/{id}/signup`（需登录）

## 选课（阶段 8；2026-10-08 规则：**人数限额制，无候补队列**）

> **规则总览**：200 门课程 / 300 个教学班；选课 = 抢名额（先到先得，**满员直接拒绝，不进候补**）；
> 自动检测时间冲突（同周几 + 节次区间重叠）；防重复选课；退课立即释放名额（可重选）。

### 12.1 课程列表

`GET /api/course/list?college=&courseType=&keyword=&pageNum=&pageSize=` → 课程分页（含班级数 / 总容量 / 已选
+ **当前用户已选标记**：`mySelected`（是否已选任一教学班）、`myClassName`（已选班级名，如 "02班"，未选为 null））

### 12.2 教学班列表

`GET /api/course/{courseId}/classes`（需登录）

**响应**：`[{ id, className, teacher, semester, capacity, selected, available, weekDay, startSection, endSection, startWeek, endWeek, location, myStatus }]`

`myStatus`：`SELECTED`（我已选）/ `DROPPED`（我退过）/ `null`（未操作）。

### 12.3 选课

`POST /api/course/select`（需登录）

```json
{ "classId": 7002 }
```

**规则链（阶段 21 受理制，默认开启；`campus.stock.async-select-enabled=false` 一键回退到下方老链路）**：
① **ACCEPT Lua 一次原子受理**——幂等两态（5 秒窗口）→ 快速已选检查（`campus:sel:{userId}`）→
余量边界检查（`campus:stock:{courseId}` 为受理真相）→ 扣减 + 版本 +1 + 写受理台账（pending）各一步；
② 发落库消息（MQ `campus_course_select_topic`，300ms 超时；**失败 → 补偿回滚 → 40056"未被受理"**）；
③ PUBLISH 名额信号（先 MQ 后 PUBLISH：推出去的每一帧都有落库消息在路上）；④ 立即返回受理回执。

**受理回执**（成功响应，HTTP 200 / `code=0`）：

```json
{ "id": null, "classId": 7002, "courseId": 1, "accepted": true,
  "remain": 36, "version": 43, "opId": "a5a12bba630a4d6bae8b7cbfcf8642fe" }
```

- `accepted=true` 表示**已受理**（数据库经 MQ 异步落库，通常几十毫秒内完成）；
  落库结果经 SSE `settled` 事件回执（见 §21.2）；"选课成功"站内信在落库提交后发出。
- `remain` / `version` = 受理后的服务端真相（客户端立即乐观渲染，不必等信号）。

**错误码**：`40050` 教学班不存在；`40051` 重复选课（受理前快速已选检查；若受理后才被落库判重，走补偿+`settled(ok=false)` 回执）；
`40052` 名额已满（受理层直接拒绝，未改任何状态）；`40053` 时间冲突（受理通过但**落库被拒 → 自动补偿**，`settled(ok=false)` 携带原因）；
`40055` 抢课高峰限流（Sentinel）；**`40056` 受理失败——落库消息发送异常，已补偿回滚，什么都没发生，可安全重试（阶段 21 新增）**。

**老链路规则链**（回退开关关闭时 / Redis 异常降级时）：① 锁用户行 → ② 重复选课检查 → ③ 时间冲突检查 →
④ 原子占名额（`UPDATE ... WHERE selected<capacity`）→ ⑤ 写选课记录；响应为同步落库后的完整课表项（`accepted` 为空）。

### 12.4 退课

`POST /api/course/drop`　`{ "classId": 7002 }`

状态置 `DROPPED` + 释放名额（同一事务，**保持同步落库**——非热点，且"失败即未退"语义最清晰）；
同步链路名额结构 +1 并推送信号，同时从该用户的"已选集合"移除（可重新选入）。**无候补队列**——名额直接回到池子，先到先得。

**错误码**：`40054` 未选该教学班（或已退课）。**边界**：若刚受理（尚未落库）就退课，可能短暂返回 40054（客户端在 `settled` 回执前显示"处理中"，正常点不到退课）。

`GET /api/course/my`（需登录）→ `[{ classId, courseCode, courseName, credits, className, teacher, weekDay, startSection, endSection, startWeek, endWeek, location, semester, createTime }]`（按周几 + 节次排序）

## 名额实时同步（阶段 20 · 只读侧；写路径契约不变）

### 20.1 名额快照（教学班粒度）

`GET /api/course/{courseId}/stock?version=<v>`（需登录）

- `version` 可选：仅用于服务端 L1 进程内缓存直返（命中即 0 次网络调用）；不传则强制走分布式缓存/回源（"校准轮"用）。
- 响应：`{ courseId, cver, serverTs, degraded, classes: [{ id, v, remain, capacity }] }`
  - `cver` = 服务端当前课程版本（永远返回真实值，客户端据此判新旧）；`degraded=true` = L3 兜底（未写缓存）。
  - **remain 仅供展示/乐观渲染；"能不能选上"一律以服务端（预扣闸门 + DB 条件更新）为准。**

### 20.2 名额信号订阅（SSE）

`GET /api/course/stock/stream?courses=<id,id,...>`（需登录；`Accept: text/event-stream`）

- 事件：`ready`（`{"courses":[...],"ts":...}`，建连即发，客户端据此拉齐）→ `stock`（严格三字段 `{"id":<教学班id>,"v":<版本>,"remain":<剩余>}`）→ `:hb` 注释帧（25s 心跳）。
- 限制：单实例 5000 连接 / 单用户 3 条 / 单连接 200 个教学班；超限返回业务错误（前端据此降级轮询）。
- 鉴权：与普通请求相同的 `Authorization` 头（前端用 fetch+ReadableStream 消费，原因：原生 EventSource 无法带自定义头）。

### 20.3 观测计数

`GET /api/course/stock/metrics`（需登录）→ 推送/发布/收到信号/扇出帧/连接数/L1 命中与未命中/重建/降级/对账等计数。

## 受理制（阶段 21 · 真相在 Redis + MQ 异步落库）

### 21.1 受理回执与语义

`POST /api/course/select` 的响应契约见 §12.3（`accepted/remain/version/opId`）。核心语义：

- **`code=0` = 已受理**（Redis 原子裁决完成、落库消息已发出），不代表已落库；
- 落库成功/被拒都会在下文 `settled` 事件里告诉本人；被拒时**名额已自动退回**并附拒绝原因（同 40053/40051/40052 的提示语）；
- 受理层拒绝（满员/重复/已选）不产生任何状态变更，也不会收到 `settled` 事件。

### 21.2 受理结果回执（SSE `settled`，按用户定向推送）

事件：`settled`，数据：`{"classId":<教学班id>,"ok":true|false[,"reason":"..."]}`。

- `ok=true`：已落库（"选课成功"站内信随后到达）；
- `ok=false`：落库被拒（`reason` 为冲突/满员等人类可读原因），**名额已退回**，客户端应回滚"已选"渲染。
- 与 `stock` 信号同一条 SSE 连接、同一鉴权；离线用户由"超时兜底刷新 + 站内信"兜底。

### 21.3 观测计数（阶段 21 增补）

`GET /api/course/stock/metrics` 增加：`accepted`（受理成功）/ `acceptFull` / `acceptDup` / `acceptAlready` /
`acceptInit`（冷启动恢复次数）/ `acceptDegraded`（降级同步老链路）/ `mqFail` / `compensated` /
`settledOk` / `settledReject` / `pendingAdjudicated`（超时裁决）。

> 一键回退：`campus.stock.async-select-enabled=false`（重启生效）→ 全部回到阶段 19/20 的同步落库链路，
> 请求/响应契约随之回到 §12.3 老链路形态。

## 预约（阶段 5；业务规则 2026-10-08 调整）

> **规则总览**：图书馆（逸夫楼）不限次、单次 1~4 小时；**体育馆每人每周限 4 次**（取消回退，爽约不回退）、**单次最长 3 小时**；均仅可预约**当天与明天**；
> **签到窗口** = 开始前 30 分钟 ~ 开始后 15 分钟，超窗未签到 → 判爽约并**禁约 24 小时**（"次日无法预约"）；
> **取消**：图书馆无惩罚；体育馆/讲座临近 30 分钟内取消 → **禁约 5 分钟**；
> **无人工审批**：机器按规则自动处理（游泳馆同普通场馆）。

### 10. 创建预约

`POST /api/reservation/create`（需登录）

```json
{ "resourceId": 10004, "slotDate": "2026-10-09", "startTime": "14:00", "endTime": "16:00" }
```

规则：整点、1~4 小时、08:00~22:00、**仅可预约当天与明天**（2026-10-08 规则；时间片表仍预生成 14 天库存）、时段尚未开始。

**响应**：`{ id, reservationNo, resourceName, slotDate, startTime, endTime, status, ... }`

**错误码**：`40020` 资源不可约 / `40021` 时段不合法 / `40022` 超窗口 / `40023` 与已有安排冲突 / `40024` 手慢了被约满 / `40026` 重复预约 / **`40029` 被限制预约（爽约或临近取消，提示含解禁时间）**。

### 10.1 签到

`POST /api/reservation/{id}/checkin`（需登录）

窗口：开始前 30 分钟 ~ 开始后 15 分钟。超窗未签到 → 定时任务（每 60 秒）自动判 NO_SHOW：释放座位 + 禁约 24 小时。

**错误码**：`40030` 不在签到窗口 / `40031` 已签到 / `40028` 非本人预约。

### 11. 取消预约

`POST /api/reservation/{id}/cancel` → 释放时间片 + 清位图 + 状态置 CANCELLED（同一事务）

临近取消惩罚（2026-10-08 规则）：**仅体育馆与讲座**——距开始不足 30 分钟取消 → 禁约 5 分钟
（Redis 惩罚，TTL 到期自动解除）；**图书馆取消无任何惩罚**。

**错误码**：`40027` 不可取消（已开始/终态）/ `40028` 非本人预约。

`GET /api/reservation/my?status=&pageNum=1&pageSize=10` → `{ total, list }`（含资源名/位置）

## 并发压测（阶段 9 起 · 演示接口）

`POST /api/stress/run`（需登录）

```json
{ "scenario": "OVERSELL", "threads": 100 }
```

| scenario | 场景 | 默认并发 | 预期 |
|---|---|---|---|
| `OVERSELL` | 100 个不同用户并发抢专用场地 10 个名额 | 100 | 恰好 10 成功，无超卖 |
| `DUPLICATE` | 同一预约并发提交 50 次 | 50 | 恰好 1 次成功 |
| `BITMAP` | 同一用户并发抢 50 个座位的同一时段 | 50 | 恰好 1 个成功 |
| `COURSE_OVERSELL` | 100 人并发抢压测班 10 个课额 | 100 | 恰好 10 成功 |
| `RATE_LIMIT`（阶段 14） | 120 人并发抢课（经 Sentinel 限流切面，QPS 阈值 20） | 120 | 超阈值被限流（40055）且成功数 ≤ 课额；实测：95 拦截 / 10 抢到 / 0 系统异常 |
| `PREDEDUCT`（阶段 17） | **1000 人**并发抢课（先过 Redis 预扣闸门） | 1000 | Redis 拦截 = 请求数 − 名额数、放行 = 名额数；实测 **990 / 10 / 407ms** |
| `IDEMPOTENT`（阶段 18） | 同一用户并发提交同一笔预约 100 次 | 100 | 恰好 1 次成功，其余 **40060** 幂等拦截；实测 99 次 |
| `LOCK`（阶段 18） | 100 线程同抢一把 Redis 分布式锁 | 100 | 进入临界区 1 次、**互斥性违例 0** |

**响应**：`{ conclusion, requests, success, failures{code:次数}, durationMs, p50Ms, p95Ms, maxMs, assertions[], detail }`

每轮压测自动清理本轮写入（含**预扣计数器**与**幂等键**，保证复跑可复现；夹具见 `migrate-stress-fixtures.sql`；
完整报告见 [docs/06](06-并发压测报告.md) §2/§8/§9）。
